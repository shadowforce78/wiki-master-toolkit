# Discard by cached price · v4.29.0

The **Discard** button sits immediately after **Plus chères** in the collection toolbar. It opens immediately from the same cached collection and permanent prices as the ranking, sorted in the opposite direction: cheapest first. Opening or recalculating the preview makes no network requests and does not load prices a second time.

1. Click **Discard** and choose a maximum average in W (default `0`). **Raretés à défausser** starts with **C and PC only** each time the modal opens. R, SR, UR and L are excluded regardless of price, unless explicitly checked. Changing rarities updates the cached selection immediately and clears confirmation; choosing no rarity disables discard. The same rarity restriction is checked before POST and throughout execution. **Recalculer la sélection** rereads the local cache after new prices arrive; it makes no network requests. If the collection cache is incomplete or missing owned-copy IDs, **Charger la collection complète** appears to fetch and save ownership once. It does not fetch prices.
2. Review the copies sorted by increasing price, with thumbnails, full wrapping names, rarity badges, copy numbers and a separate price column. Every eligible copy across all pages is selected automatically. Uncheck any copies you want to keep; the preview's page controls do not restrict the overall selection.
3. Tick the explicit confirmation checkbox, then click **Défausser N exemplaire(s)**. This permanently discards the selected copies. The whole collection and protection data are checked again before the first request. New cards obtained after the preview are never silently added.
4. Watch progress. **Arrêter** prevents later batches; a request already sent may finish. After a mutation, closing with **Fermer et actualiser le site** refreshes the site's cards and balance. There is no separate generic refresh button.

Favorites, shiny cards, pending-trade cards, and cards with active sales are always protected during execution. Cached protections are used in the immediate preview; old cache formats without per-copy/protection details still work, with a mandatory fresh protection check after confirmation and before any POST. Newly protected/missing copies stop execution and require a new preview/confirmation. The auction response exposes catalogue IDs, so all copies of a listed card are conservatively protected. If the protection request fails, pagination is incomplete, ownership fields are missing, or copies repeat across pages, no discard is sent.

A successful summary with no average for the copy's exact rarity (**Moy. —**) counts as **0 W for discard selection**, as does a numeric average of zero. The stored summary and ordinary card price display remain unchanged; another rarity's average is never substituted. Missing cache entries, API errors, queued/in-flight requests and unfinished saved price work are excluded, even when an older successful price is retained. Malformed results are excluded. These are historical cached averages, not a guarantee of current or future market value. Use the existing **Charger les prix** toolbar button separately to load or refresh prices, then **Recalculer la sélection**.

Execution sends fixed owned-copy IDs in sequential batches of 50, with 500 ms between completed batches. You can therefore select more than 50 copies across pages without repeatedly using the site's selection controls. A changed price, newly protected/missing copy, server block, partial success, invalid response or network failure stops further work. A mutation request is never automatically retried. Unknown results remain visibly unconfirmed and must be checked on the site before another manual run. No job resumes after reload. The last local execution report is available under `wm_discard_report_v1`.

Full ownership reads save reusable metadata and per-copy favorite/shiny flags in the same collection cache. Successful removals update that metadata used by the ranking. Uncertain results invalidate those ownership claims rather than offering potentially removed copies for sale. Existing caches need no reset or migration. Price history and pull/drop statistics remain intact. File sync exports prices/statistics only; it does not replicate discard jobs or execute them on another computer.

## Research evidence

- Read-only inspection of installed [WikiMasters QoL](https://chromewebstore.google.com/detail/wikimasters-qol/cdgbnhgpnjpefcpdneggdbdfpfpiokml) v0.19.10: `src/api.js` calls `POST /api/user-cards/bulk-discard` with JSON `{ "card_ids": [ownedCopyId, ...] }`; `src/discard.js` scans paginated collection entries and attempts batches of 100. Its discard criteria are rarity/duplicates/q_score, rather than our cached average prices. The installed package was not changed.
- WikiMasters' actual collection client, observed in its loaded `14yi4kchm5v2m.js` chunk, uses that same POST endpoint/body and reads `discarded_count` plus `failed`. Its interface calculates collection pages with a size of 50. The request has copy IDs, with no page identifier. The true server maximum was not destructively probed; this implementation stays at the native interface's 50-copy batch size.
- Read-only live calls verified that `/api/my-collection?sort=rarity&page=0&stats=1` returns owned row `id`, catalogue `card_id`, per-copy `starred`/`is_shiny`, `total` and `pendingTradeCardIds`. `/api/marketplace?page=1&limit=50&sort=recent&mine=1` returns the `selling` array. `/api/marketplace/mine` alone only supplied counts and is insufficient for copy protection.
- No real cards were discarded during research or testing. The real site's mutation behavior, cross-page batches and server limits remain dependent on its implementation; the extension stops visibly on refusal.

## Verification

The v4.29.0 checks target the rarity change: two focused behavior tests verify C/PC defaults, cheap/no-average R/SR/UR/L exclusions, empty/invalid selections and enforcement before POST and after fresh ownership verification. The existing Chromium integration verifies C/PC controls, immediate filter changes, clearing confirmation, explicit R opt-in, cached thumbnails/names and 50/50/25 fixture execution while a zero-priced R copy survives. `artifacts/discard-preview-v4.29.0.png` shows the synthetic local preview. Full unrelated unit suites were not repeated. No real cards were discarded.

## Pack summary actions

The **Tout ouvrir** summary lists a checkbox per pulled card, a **Tout sélectionner** box, and two actions:

- **Mettre aux enchères (N)** lists each selected card one after the other with the shared price and duration fields (default 10 W, 10 min), using the same listing flow as the ranking. A card whose only available copy is a favorite is skipped, never sold.
- **Défausser (N)** asks for confirmation, rereads the whole collection, then discards one unprotected copy per selected card. Favorites, shiny copies and copies in a pending trade or a sale are never picked; those cards are reported as protected and left alone. If a batch result is uncertain, actions lock until the summary is closed (which refreshes the site).
